# Руководство Администратора (ADMIN GUIDE)

## 1. Первичная выдача прав Администратора
По соображениям безопасности ни один донат-ранг (включая `GOD`) не имеет административных прав. Чтобы выдать себе права владельца из серверной консоли:
```text
reallycore setrank ВашНик ADMIN
lp user ВашНик parent set admin
```

---

## 2. Главная административная команда `/reallycore` (`/rc`)
Требует право `reallycore.admin`:

| Команда | Назначение |
|---|---|
| `/rc status` / `/rc modules` | Показать статус и health-check всех 19 модулей `ReallyCore` |
| `/rc diagnostics` | Вывести TPS, потребление памяти JVM, аптайм, состояние SQL и активный ивент |
| `/rc reload` | **Безопасная горячая перезагрузка** всех 25 YAML-конфигов без кика игроков (НЕ используйте `/reload`!) |
| `/rc debug` | Переключить расширенное логирование отладки |
| `/rc buildspawn` | Построить/восстановить архитектуру Спавна, Колизея, Автошахты, 8 NPC и 7 голограмм |
| `/rc giveitem <ник> <тип> <id> [шт]` | Выдать подписанный кастомный предмет (`SPHERE`, `TALISMAN`, `ARTIFACT`, `WEAPON`, `ARMOR`, `CONSUMABLE`) |
| `/rc givekey <ник> <кейс> <шт>` | Начислить ключи любого из 8 кейсов (`donate`, `rilliks`, `spheres`, `talismans`, `prefixes`, `coins`, `kits`, `mythic_event`) |
| `/rc startevent <id>` | Принудительно запустить мировой ивент (`airdrop`, `meteorite`, `talisman_capture` и др.) или босса (`ancient_guardian`, `fire_titan`, `void_lord`, `dark_knight`, `dragon_warrior`) |
| `/rc stopevent` | Остановить активный мировой ивент и деспавнить активного босса с очисткой блоков |
| `/rc setrank <ник> <ранг>` | Установить игроку ранг (`PLAYER`, `HERO`..`GOD`, `HELPER`, `ADMIN`) с синхронизацией в LuckPerms |

---

## 3. Управление экономикой и варпами
- **Монеты:** `/eco give <ник> <сумма>`, `/eco take <ник> <сумма>`, `/eco set <ник> <сумма>`
- **Риллики (донат-валюта):** `/rilliks give <ник> <сумма>`, `/rilliks take <ник> <сумма>`, `/rilliks set <ник> <сумма>`
- **Точка спавна и варпы:** `/setspawn`, `/setwarp <id> <название>`, `/delwarp <id>`

---

## 4. Модерация и расследование инцидентов
- Все денежные операции неизменяемо записываются в таблицу `economy_transactions` (UUID транзакции, баланс до/после, причина, время).
- Подозрительные действия (попытки пакетного спама, обхода команд, переполнения книг) фиксируются в `security_audit_log`.
- История разрушения/установки блоков и кликов по сундукам проверяется через **CoreProtect**: `/co inspect`, откат грифа: `/co rollback u:<ник> t:1h r:20`.
